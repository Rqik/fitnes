# FIT-005 · Замер из показателя

Дизайн-передача от 19 ноября 2026 года. [Кликабельный концепт](FIT-005.html) открывается локально и содержит демонстрационные данные. Сценарии записи, исправления, ошибок, целей, профиля и переноса меняют данные внутри открытого макета. Обновление страницы возвращает исходный пример.

Unslop применён к иерархии и взаимодействию. Убраны повторные вводные, декоративные значки и одновременные редакторы. Палитра «Графит и сталь» взята из проекта. Выделенный элемент — текущее значение и его динамика. Характер — точный, спокойный, повседневный. Повторяемая деталь — число рядом с единицей и датой фактического замера. Методика [unslop Дамира Соколовского](https://github.com/heydamir/unslop), CC BY 4.0.

Браузерная проверка действующего приложения на 390×844 подтвердила 13 видимых полей в диалоге «Новый замер». Верх кнопки сохранения оказался на 1419 px, начальный фокус — на дате. Это определяет приоритет быстрого редактора одного значения.

## Ежедневная запись

1. В обзоре виден последний вес, его дата и основное действие «Записать вес». Строки остальных показателей тоже открывают запись. На карте пользователь выбирает зону и нажимает «Записать талию» либо действие другого выбранного показателя.
2. Открывается один редактор с названием показателя. Для новой записи поле пустое. Последнее значение с датой показано обычным текстом над полем. Единица закреплена справа от числа.
3. Дата по умолчанию — сегодня, видимой строкой. «Другая дата» раскрывает календарь. Дата не получает начальный фокус. Клавиатура телефона предлагает десятичный ввод.
4. Пользователь вводит число и нажимает единственное основное действие «Сохранить». Enter выполняет то же действие. Сохранение не происходит при потере фокуса.
5. После успешного сохранения диалог закрывается, обновляются значение, дата, история и график. Рядом с итогом «Вес 80,9 кг · сегодня» остаётся действие «Исправить». Сообщение не исчезает по таймеру.

Редактор с компьютера и телефона одинаков по содержанию. На компьютере это компактный диалог шириной до 440 px. На телефоне — нижний лист с прокруткой, высотой по содержимому и максимумом по доступному окну. Поле и кнопка остаются доступны при появлении экранной клавиатуры. Нативный dialog обеспечивает модальность и возврат фокуса. Основные элементы имеют область касания не меньше 44×44 px.

| Состояние | Вид и действие |
| --- | --- |
| Первый замер | «Замеров ещё нет», пустое числовое поле, единица и дата сегодня |
| Есть прошлый замер | «Последний замер 81,2 кг · 16 ноября». Значение не переносится автоматически в новый день |
| На выбранную дату показатель уже записан | Заголовок «Исправить вес», поле содержит значение этого дня, подпись «Записано 81,2 кг». Остальные показатели дня не затрагиваются |
| Неверное число | Сообщение под полем, aria-invalid, фокус на поле. Запятая и точка допустимы, поддерживается точность до двух знаков |
| Сбой сохранения | Число и дата остаются в поле. «Не удалось сохранить. Повторите попытку» и та же кнопка сохранения |
| Конкурентное изменение | В реализации перечитать актуальное значение этого показателя, показать «Замер изменился в другой вкладке» и предложить проверить значения перед повторной записью |
| Закрытие с черновиком | Escape или «Закрыть» открывают внутри редактора вопрос о черновике. Действия «Продолжить ввод» и «Закрыть без сохранения», начальный фокус на продолжении |
| Пустой редактор закрывается | Диалог закрывается одним действием, фокус возвращается к источнику |

Действие «Исправить» открывает тот же показатель на сохранённую дату с заполненным полем. Исправление остаётся доступно из истории после ухода со страницы. История показывает строки отдельных значений внутри дня. Изменение одного числа не заменяет весь день.

## Редкие действия

«Несколько показателей» находится вторичным действием в обзоре и внутри редактора. Оно открывает пакетный ввод на выбранную дату. При переходе текущий черновик переносится. Начальный список содержит выбранный показатель и талию. «Добавить показатель» раскрывает перечень. Каждый выбранный показатель получает ровно одно числовое поле и единицу. Пустые выбранные поля пропускаются. Перед сохранением кнопка показывает количество введённых значений. Сохранение атомарно сливает заполненные показатели в запись дня.

Календарь открывается по «Другая дата», включая пакетный режим. Будущие даты отклоняются. При смене даты набранное число остаётся в черновике. Если на новую дату уже есть значение, оно подписывается как заменяемое. Перенос даты исторической записи выполняется отдельным действием «Перенести на дату» в полном редакторе дня и не входит в быстрый ввод.

В целях сначала видны результат, текущее значение и остаток по каждой цели. Контекстное «Изменить» открывает уже выбранный показатель. Формулировки условия — «Не больше», «Не меньше», «Диапазон». Новая цель просит выбрать условие, затем значение. Для диапазона появляются два поля. «Сохранить цель» — единственный основной CTA. Удаление цели имеет подтверждение с названием и условием. Фокус меняется через компактный отдельный выбор, без постоянной анкеты.

В сравнениях выбранная группа занимает одну строку. «Изменить» открывает возрастную группу и пол в таблицах NHANES. Сохранение явное. Пустой профиль оставляет личную динамику доступной и предлагает выбрать группу для сравнения. На первом экране не запрашиваются имя, дата рождения, рост или вес повторно.

В «Моих данных» находятся «Перенести из Apple Health», «Скачать копию», «Восстановить копию». Apple Health после чтения файла показывает период, число новых значений, совпадений и конфликтов. Подтверждающая кнопка указывает число новых значений. Существующие значения сохраняются при конфликте, политика подписана перед действием. Для восстановления JSON остаётся подтверждение замены с числом записей и названием файла. Выгрузка копии выполняется сразу. Ошибки чтения выводятся рядом с действием выбора файла, текущий дневник сохраняется.

В прототипе Apple Health показывает обозначенный демонстрационный предпросмотр, после подтверждения добавляет три синтетических значения. Настоящие ZIP/XML разбираются действующим импортёром приложения. JSON-выгрузка и загрузка в прототипе работают с его собственным демонстрационным форматом.

## Макеты и передача

| Ширина | Композиция |
| --- | --- |
| 1440 px | Навигация 240 px, края контента 32 px. Основная колонка около 2/3 ширины, боковой блок текущего показателя около 1/3. График шире списка. Диалог до 440 px |
| 390 px | Поля страницы 20 px, одна колонка, шапка с «Меню». Текущий показатель и действие до графика, строки замеров от 64 px. Редактор нижним листом, поле 48 px |
| 320 px | Поля 16 px, перенос длинных подписей. Число и единица не разделяются переносом. Строки и лист сохраняют 44 px для действий. Ввод и даты не создают горизонтальную прокрутку |

Карта в концепте использует встроенный существующий атлас, который сохраняется внутри HTML. Фигура и выбор зоны служат проверке общего входа в редактор. В реализации повторно используется текущая карта с её сводкой и всеми зонами.

Будущий источник фото и ИИ добавляется к выбору способа получения черновика. Последовательность — выбрать снимок, получить предложения, проверить значения и единицы, скорректировать каждое предложение, подтвердить запись. У каждого предложения есть источник, дата и отметка проверки. Непроверенные значения не попадают в статистику. Эта последовательность описана в передаче, кнопки анализа в текущем прототипе отсутствуют.

Потребуются единый редактор одного показателя, открываемый с параметрами metric, date и режимом записи/исправления, общая точка атомарного сохранения одного или нескольких показателей и устойчивый результат с действием исправления. Каталог показателей, их единицы, валидация, IndexedDB и schemaVersion 1 переиспользуются. Будущий импорт фото получает контракт черновика отдельно от сохранённого журнала.

## Приёмка

- Открыть концепт на 320, 390 и 1440 px. Проверить обзор, карту, историю, цели, сравнения и данные, включая открытый редактор.
- Из обзора записать новый вес. До ввода поле пустое, прошлый замер остаётся справкой. После сохранения исправить число, затем найти исправление в истории.
- Из карты выбрать талию и сохранить её на ту же дату. Вес этого дня сохраняется.
- Ввести ноль, неверный текст и долю мышц выше 100%. Получить сообщение у поля. Исправить число и повторить сохранение.
- В раскрытии «Проверка макета» включить «Сбой следующего сохранения». Число остаётся после ошибки, повторное сохранение проходит.
- Проверить календарь, пакетный ввод и отмену несохранённого черновика. Заполненный черновик переносится в пакетный режим.
- С клавиатуры пройти выбор показателя, ввод, сохранение, исправление, диалог и Escape. Фокус виден и возвращается к источнику.
- Скачать демонстрационный JSON, изменить дневник и восстановить файл после подтверждения. Повреждённый файл отклоняется.

Проверка прототипа выполнена в установленном Chrome 19 ноября 2026 года. Пройдены новая запись с пустым полем, исправление, ошибка нуля, Escape с черновиком, сбой сохранения и повторная запись, пакетное слияние, редактирование цели и профиля, выгрузка и восстановление JSON, отказ повреждённого файла. Дополнительно проверены доля мышц больше 100%, сохранение набранного значения при смене даты и демонстрационный импорт.

Все шесть разделов проверены на 320, 390 и 1440 px. Горизонтальной прокрутки нет. Кнопка «Сохранить» видна в редакторе при этих ширинах и высоте окна 844 px на телефоне. Установленный на компьютере Chrome использовал изменение размеров окна. Поведение настоящей экранной клавиатуры iPhone требует отдельной проверки на устройстве при реализации.

На карте прототипа используются независимые контуры FIT-006 из атласа. Клавиатурный выбор зоны проверен на обоих ракурсах. Браузерная проверка завершилась с нулём ошибок JavaScript и внешних сетевых запросов. Результат FIT-005 передаётся в разработку как спецификация и автономный прототип.
